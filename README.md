# 音分け — Otowake

アプリごとに音声の出力先、音量、ミュートを設定するmacOSのメニューバーアプリです。

たとえばChromeをモニター、ChatGPTをイヤホンへ同時に出力できます。音声制御をOFFにすると、各アプリは通常の音声出力に戻ります。

## 起動

ビルド済みアプリは `dist/Otowake.app`、ZIPは `dist/Otowake-macOS.zip` にあります。

```sh
open dist/Otowake.app
```

macOS 14.4以降が必要です。ビルド済みアプリはApple Silicon／Intel両対応です。

1. メニューバーのスライダーアイコンを開きます。初回は案内ウインドウも開きます。
2. 「すべて表示」で起動中のアプリを表示するか、対象のアプリで音声を再生します。
3. アプリごとに出力先・音量・ミュートを設定します。
4. 右上のスイッチで音声制御を有効にします。
5. macOSから求められた場合は「システムオーディオ録音」を許可します。

初期状態は制御OFFです。標準出力・100%・ミュートなしのアプリには音声タップを作成しません。音量は0〜100%で、ミュート解除時は元の音量が維持されます。

出力先が未接続になると、設定を保持したまま制御を解除し、アプリ本来の出力に戻ります。再接続すると自動で設定を適用します。終了時や制御OFF時にもタップを破棄します。Macの標準出力先やシステム全体の音量は変更しません。

## 設定の保存

`~/Library/Application Support/Otowake/settings.json` に自動保存します。アプリはBundle ID、デバイスはUIDで識別するため、PIDや一時的なデバイス番号が変わっても設定を維持できます。設定メニューから保存先を開けます。

壊れた設定や新しいバージョンの設定を読み込んだ場合は警告を表示し、元ファイルを上書きしません。修正するか別名に退避してから再起動してください。

## ビルドとテスト

Xcode 16以降のCommand Line ToolsとSwift 6が必要です。検証環境はXcode 26.3／Swift 6.2.4／macOS 26.6.2です。外部パッケージのダウンロードは不要です。

```sh
Scripts/swift.sh test
Scripts/build.sh                 # 開発Macのアーキテクチャ
Scripts/build.sh --universal     # Apple Silicon + Intel
```

`Scripts/swift.sh` はキャッシュをプロジェクト内に置くSwiftPMラッパーです。アプリのサンドボックス設定を変更するものではありません。

ローカル用アプリはアドホック署名します。自分のMacでの開発・利用に有料のライブラリやDeveloper IDは不要です。一般配布用のDeveloper ID署名・公証は含んでいません。署名証明書を持っている場合は `OTOWAKE_SIGNING_IDENTITY` で指定できます。公証は別途行ってください。

読み取り専用の診断：

```sh
dist/Otowake.app/Contents/MacOS/Otowake --diagnose
```

実機の転送テスト（小さな合成テスト音が流れます）：

```sh
# 標準出力に1つの独立したテスト音源を転送
dist/Otowake.app/Contents/MacOS/Otowake --smoke-test

# --diagnoseで表示されたUIDを指定すると、複数音源を別々の出力先へ同時転送
dist/Otowake.app/Contents/MacOS/Otowake --smoke-test 'DEVICE_UID_1' 'DEVICE_UID_2'
```

このテストは既存アプリの音声には触れず、`afplay`の合成音源だけを取得します。音声バッファ、ゲイン、ミュート、タップ解放を検証します。スピーカーからの実際の音圧や主観的な音質は測定しません。

## 音が変わらない・出ない場合

- 制御スイッチと、アプリ側の音量・出力先を確認してください。
- 「?」から録音の許可を確認し、必要に応じて音分けを再起動してください。macOSの版によって設定項目名は「画面とシステムオーディオ録音」などになります。
- 「音声制御を再接続」でルートを作り直せます。
- ローカルのアドホック署名では、アプリを再ビルド・更新した際にmacOSが音声取得の許可を再確認する場合があります。
- APIエラーや不正なバッファ・開始済みIOの停止が続く場合は、制御を解除して通常のアプリ再生へ戻します。再生前や無音のストリームは「音声の開始を待機中」として保持し、音声が始まると設定を適用します。
- 終了すると制御を解除します。ログイン時の自動起動は実装していません。

SafariのWebKit音声も所有元のSafariにまとめます。XPCサービスの所有元特定に、利用可能な場合だけ呼び出す非公開のmacOS SPIを1つ使用します。将来のOSで利用できなくなった場合は親プロセス探索に戻ります。DRMで保護された音声、排他モードの機器、アプリ独自の音声経路、所有元を特定できない共有XPC音声サービスには制限があります。ブラウザのタブ単位の制御には対応しません。USBの特殊なマルチチャンネル構成やBluetoothのプロファイル変更は各機器での追加検証が必要です。

技術選定・構成は [Docs/ARCHITECTURE.md](Docs/ARCHITECTURE.md)、実施した検証と限界は [Docs/VALIDATION.md](Docs/VALIDATION.md) を参照してください。

## プライバシーとライセンス

音声はローカルのメモリ内で転送・処理します。録音ファイルの保存、ネットワーク送信、解析サービス、広告、外部SDKはありません。マイクを使う機能もありません。

Swift／SwiftUI／AppKit／Core Audioと小さなC11音声処理で構成しています。プロジェクトのコードはMITライセンスです。
